# Behance 포트폴리오 검색 결과 페이지 디자인 시스템

## 프로젝트 정보
- **출처 이미지**: Behance "포트폴리오" 검색 결과 페이지 전체 캡처 (`lecture1/behance-portfolio-search-full.png`, 1023×4371px), 첫 화면 캡처 (`lecture1/behance-portfolio-search.png`, 1038×658px)
- **분석 날짜**: 2026-07-08
- **적용 프로젝트**: my-react-app (lecture1) 디자인 레퍼런스
- **분석 방식**: Playwright MCP로 페이지 접속 후 accessibility snapshot(DOM 구조)과 전체 페이지 스크린샷을 함께 확보. 스크린샷은 Python Pillow로 행/열 단위 픽셀 스캔(배경-전경 임계값 비교)을 수행해 카드 폭·그리드 간격·모서리 형태를 실측. 컬러 값은 분석 범위에서 제외.
- **문서 포맷 참고**: `DesignSystem/BOOK_DesignSystem.md`

## 1. 타이포그래피

### CSS 변수 정의
```css
:root {
  /* Font Size Scale */
  --font-size-h1: 1.75rem;      /* 28px - 히어로 카피 ("세계 최고 수준의 크리에이터...") */
  --font-size-nav: 1rem;        /* 16px - 상단 내비게이션 / 탭 / 정렬 버튼 텍스트 */
  --font-size-card-title: 1rem; /* 16px - 카드 제목 */
  --font-size-card-meta: 0.875rem; /* 14px - 카드 통계(좋아요/조회수)·작성자 텍스트 */
  --font-size-caption: 0.75rem; /* 12px - 푸터 링크, 카테고리 배지 라벨 */

  /* Font Weight */
  --font-weight-semibold: 600;  /* 카드 제목, 섹션 헤딩 */
  --font-weight-regular: 400;   /* 본문/메타 텍스트 */

  /* Line Height */
  --line-height-heading: 1.3;
  --line-height-body: 1.5;
}
```

### 타이포그래피 사용 가이드
- **`--font-size-card-title` (16px / semibold)**: 카드 하단 첫 줄 텍스트. 카드 내부 요소 중 가장 굵고 큰 글자로, 스캔 시 시선이 가장 먼저 닿는 지점이다.
- **`--font-size-card-meta` (14px / regular)**: 좋아요·조회수 숫자 및 작성자명. 제목보다 한 단계 작고 얇아 위계가 분리된다.
- **`--font-size-nav` (16px)**: 검색창, "프로젝트/인물/기타" 탭, "정렬 - Recommended" 버튼 등 조작 영역 텍스트에 공통 적용.
- **`--font-size-caption` (12px)**: 카테고리 캐러셀 칩 라벨, 푸터 링크 리스트처럼 항목 수가 많고 위계가 낮은 텍스트.

> 측정 근거: 전체 페이지 캡처(1023px 폭)에서 카드 1개 열의 제목 텍스트 라인 높이를 픽셀 스캔으로 확인한 결과 약 11px(캡 하이트) → 표준 폰트 사이즈 환산 시 약 15~16px에 대응했다. 이를 8px 그리드 기준 표준 타입 스케일(16px)로 보정했다.

## 2. 간격(Spacing) & 그리드 레이아웃

### CSS 변수 정의
```css
:root {
  --spacing-xs: 0.5rem;   /* 8px */
  --spacing-sm: 1rem;     /* 16px */
  --spacing-md: 1.5rem;   /* 24px - 카드 열(column) 사이 gap, 페이지 좌우 여백 */
  --spacing-lg: 2rem;     /* 32px - 카드 행(row) 사이 gap */

  --grid-columns: 3;
  --grid-column-gap: 1.5rem; /* 24px */
  --grid-row-gap: 2rem;      /* 32px */
  --page-side-padding: 1.5rem; /* 24px */
}
```

### 간격 사용 가이드
- **`--grid-column-gap` (24px)**: 카드 그리드는 3열 고정 구조이며, 열과 열 사이 간격이 좌우 페이지 여백과 동일한 24px로 통일되어 있어 그리드와 페이지 프레임이 같은 리듬을 공유한다.
- **`--grid-row-gap` (32px)**: 카드 행 사이 간격은 열 간격보다 한 단계 넓은 32px로, 썸네일 하단 메타 텍스트 블록(제목·통계·작성자)이 다음 행 썸네일과 시각적으로 눌리지 않도록 여유를 둔다.
- **`--page-side-padding` (24px)**: 그리드가 별도의 중앙 정렬 max-width 컨테이너 없이 뷰포트 좌우에 24px 고정 여백만 두고 거의 풀블리드(edge-to-edge)로 확장되는 구조다. BOOK/디에트르 레퍼런스처럼 콘텐츠 폭을 좁게 제한하는 방식과 달리, 검색 결과처럼 항목 수가 많은 피드형 화면에서는 뷰포트를 최대한 활용하는 방향으로 설계되어 있다.

> 측정 근거: 전체 페이지 캡처에서 y=600~820 구간(카드 행 1개)을 가로로 픽셀 스캔한 결과 카드 폭이 약 315px, 카드 사이 간격이 약 24px로 3열에 걸쳐 균일하게 반복됨을 확인했다. 같은 방식으로 세로 스캔(x=180 고정) 시 1행 썸네일 하단(약 y=625)과 2행 썸네일 상단(약 y=658) 사이 간격이 약 32px로 측정되었다.

## 3. 카드 컴포넌트 구조 (Anatomy)

### CSS 변수 정의
```css
:root {
  --card-thumbnail-ratio: 1.28; /* 실측 약 315:246, 콘텐츠에 따라 가변(매스너리형) */
  --card-overlay-position-badge: top-left;   /* 카테고리 배지 */
  --card-overlay-position-save: top-right;   /* 저장(무드보드 추가) 버튼, hover 노출 */
  --card-meta-order: title, stats, author;   /* 위→아래 정보 순서 */
}
```

### 카드 구조 사용 가이드
- 카드는 3개 레이어로 구성된다: ① 썸네일 이미지(가변 비율), ② 썸네일 위 오버레이(좌상단 카테고리 배지, 우상단 저장 버튼 — hover 시 노출), ③ 썸네일 하단 메타 텍스트(제목 → 통계(좋아요/조회수) → 작성자명 + Pro 배지 순).
- 오버레이 요소(배지·저장 버튼)를 이미지 위에 배치해 메타 텍스트 레이어의 타이포그래피를 침범하지 않으면서도 핵심 액션을 이미지 자체에서 즉시 실행하게 한다.
- 카드 높이는 썸네일 비율에 따라 열마다 달라져 3열 고정 그리드 안에서도 매스너리(masonry)에 가까운 인상을 준다.

## 4. 컴포넌트 스타일 (Radius / Shadow)

### CSS 변수 정의
```css
:root {
  --radius-none: 0px;    /* 카드 썸네일 - 직각 모서리 */
  --radius-pill: 999px;  /* 검색창, 필터 버튼, 카테고리 캐러셀 칩 */
  --shadow-card: none;   /* 그림자 없이 여백만으로 카드 구분 */
}
```

### 컴포넌트 스타일 가이드
- 카드 썸네일은 `--radius-none`(직각 모서리)을 사용한다. 픽셀 스캔 결과 모서리에 곡선 처리(anti-aliasing 외 별도 radius)가 감지되지 않아, BOOK 레퍼런스의 둥근 카드(`--radius-md` 16px)와 달리 각진 그리드 인상을 준다.
- 검색창·필터 버튼·카테고리 칩은 반대로 `--radius-pill`(완전 캡슐형)을 사용해, "각진 콘텐츠 카드"와 "둥근 탐색/필터 UI"라는 두 가지 형태 언어가 역할별로 명확히 구분된다.
- 카드 구분은 box-shadow 없이 순수 여백(그리드 gap)만으로 처리되는 플랫 스타일이다.

> 측정 근거: 카드1(1행 1열) 좌상단 모서리를 18~40px 구간에서 1px 단위로 스캔한 결과, 곡선 전환 없이 y=256부터 즉시 직각으로 전경(이미지) 픽셀이 시작되어 별도의 border-radius가 없음을 확인했다.

## 반응형 고려사항
- **모바일/저해상도 화면**: 3열 그리드(`--grid-columns: 3`)는 태블릿에서 2열, 모바일에서 1열로 축소하는 것이 일반적인 패턴에 부합한다. 이때 `--grid-column-gap`/`--grid-row-gap`은 16px 내외로 함께 축소를 권장한다. (본 분석은 데스크톱 뷰포트만 실측했으며 실제 모바일 레이아웃은 확인하지 않았다.)
- **터치 디바이스**: 저장 버튼처럼 hover 시에만 노출되는 오버레이 요소는 터치 환경에서 항상 노출되거나 탭 시 노출되도록 대체해야 한다.
- **좁은 화면에서의 여백**: `--page-side-padding`(24px)은 화면이 좁아질수록 상대적으로 카드 폭을 과도하게 줄이므로, 모바일에서는 16px로 축소하는 것을 권장한다.
